## ERR-001 — ESLint errors present on both baseline and merged tree

**Severity:** P2 (cosmetic — does not block build or typecheck)
**Phase:** Quality gate, pre-commit

**Symptom**
`npm run lint` on the merged tree reported 232 problems (66 errors, 166 warnings).
Errors are `@next/next/no-html-link-for-pages` (raw `<a>` to internal routes) and
`@typescript-eslint/ban-ts-comment` (`@ts-nocheck` headers in generated components).

**Root cause**
Pre-existing debt inherited from the clone-scaffolding generation process, not
introduced by this merge. Confirmed by stashing the merge, checking out `main`,
and running the same command: `main` baseline is 243 problems (**92 errors**, 151
warnings). The merge therefore *reduces* the error count by 26.

**Fix**
None applied — out of scope for a merge task (global rule §8: no adjacent
refactoring). `tsc --noEmit` and `next build` both pass, so nothing is blocked.
Logged so the debt is visible rather than silently carried.

**Status:** Accepted, deferred.

## ERR-002 — Route smoke test produced false-negative 404s

**Severity:** P2 (test harness defect, not a product defect)
**Phase:** Post-deploy verification

**Symptom**
First smoke test of the Vercel preview returned 14-byte bodies with no `<title>`
for every route except `/` — `/about`, `/contact`, `/testimonials`,
`/tie-up-hospital`, `/syllabus-links`, `/scholarships`. Initially read as the
deployment serving only the homepage.

**Root cause**
Two compounding harness mistakes, both mine:
1. `vercel curl` was invoked without `-L`, so it did not follow the **308
   trailing-slash redirect** the site issues (`/about` → `/about/`). The 14-byte
   body was literally `Redirecting...`.
2. The first attempt also passed `-o /dev/null -w "%{http_code}"`, which
   `vercel curl` did not honour — it dumped full HTML to stdout instead of a
   status code, masking the redirect.

**Fix**
Re-ran with `vercel curl -sL`. All 9 sampled routes returned full HTML with correct
titles (`About Us`, `Contact`, `Testimonials`, `Our Tie Up Hospital`,
`Syllabus Links`, `Scholarship`, `Departments`, `M.Pharm`, `KKCP`). Added a
negative control — `/nonexistent-xyz` → `404: This page could not be found.` —
to prove the test could still distinguish a real miss.

**Lesson**
A smoke test without a negative control cannot tell "everything is broken" from
"my client is misconfigured". Always include a known-bad path.

**Status:** Resolved.

## ERR-003 — `react-hooks/set-state-in-effect` in incoming CampusCarousel

**Severity:** P2 (lint error; does not block typecheck or build)
**Phase:** Quality gate, session 2 merge of `kkcp-updates-2/`

**Symptom**
ESLint error count rose 66 → 67 against the base branch. The new one:

```
app/test-dummy-webs-1-react/_components/CampusCarousel.tsx:66:5
error  Avoid calling setState() directly within an effect  react-hooks/set-state-in-effect
```

**Root cause**
The "reset on responsive change" effect calls `setIsTransitioning(false)` and
`setCurrent(0)` synchronously in the effect body, keyed on `[slidesPerView]`:

```tsx
useEffect(() => {
  setIsTransitioning(false);
  setCurrent(0);
  const timer = setTimeout(() => setIsTransitioning(true), 50);
  return () => clearTimeout(timer);
}, [slidesPerView]);
```

This triggers a cascading render. Impact is bounded — it fires only when the
viewport crosses a breakpoint, not per frame — so it is a code-smell, not a
user-visible defect.

**Fix**
**None applied, deliberately.** The task was to merge the drop folder, and this
is incoming authored code. Rewriting a carousel's state machine is a behavioural
change outside a merge's scope (global rule §8), and doing it silently would
hide it from the author. `tsc` and `next build` both pass, so nothing is blocked.

Recorded so the +1 error is attributable rather than looking like drift.

**Status:** Accepted, deferred — flagged to the user for a decision.

## ERR-004 — Misread a 9849-line reformat as a feature rewrite

**Severity:** P2 (analysis error, caught before commit)
**Phase:** Change review, session 2

**Symptom**
`app/test-dummy-webs-2-react/_components/KkcpTree.tsx` showed +9849/-56 lines.
Initial read was that a 65-line stub had been built out into a full page — which
would have been the largest feature in the drop.

**Root cause**
Two compounding misreads:
1. The "65-line stub" was not a stub. It was the same full page, minified onto
   very long lines. Line count was a bad proxy for content.
2. Follow-up normalization (`tr -d '[:space:]'`) showed a real 55KB shrink, which
   looked like content deletion. A `<a ` token count appearing to drop 301 → 46
   reinforced this — but that was a prettier artifact: attributes moved onto
   their own lines, so `<a ` with a trailing space stopped matching.

**Fix**
Switched from line/substring heuristics to structural invariants: counts of
`</a>`, `</div>`, `</span>`, `<img>`, `href=`, `src=`, `className=`, `data-`,
`aria-`, `id=`, `style={{`, plus the full set of unique `href`/`src`/`action`
values. Every one matched exactly (301 anchors, 90 unique refs, 1012 divs…).
The 55KB was then located at byte 15104: `data-settings` moving from escaped
double-quoted JSX strings to single-quoted ones — identical JSON payload.

**Lesson**
On generated/minified files, line counts and open-tag substrings are unreliable.
Compare closing tags and attribute-value sets — they survive reformatting.

**Status:** Resolved — change correctly classified as reformat-only before commit.

## ERR-005 — CRLF line endings committed across ~354 files

**Severity:** P1 (blocks clean review of the sprint's diffs; no runtime impact)
**Phase:** Both merge sessions — introduced at import, found after production deploy

**Symptom**
Comparing `feat/kkcp-updates-2` against the upstream branch the work actually
came from, `origin/content/kkcp-md-verbatim`, showed 398 differing files. Only
**39** differ in real content — **359 are byte-identical once `\r` is stripped**.

| | this branch | `content/kkcp-md-verbatim` |
|---|---|---|
| files with CRLF | **354** | 51 |

**Root cause**
Both drop folders were authored on Windows (`-rw-rw-rw-` perms, CRLF endings).
They were copied into the repo verbatim with `cp`. The repo has **no
`.gitattributes`** and `core.autocrlf` is **unset**, so nothing normalised on the
way in. Normalising imported content is the importer's responsibility, so this is
a defect in the merge procedure, not in the drop folders.

Consequence: the committed diff is ~10× larger than the real change. Blame,
review and any future merge on those files are all polluted. The two components
added in session 2 — `HeroSection.tsx`, `CampusCarousel.tsx` — are CRLF as well.

**Runtime impact: none.** Verified against production after deploy — all 9 sampled
routes 200 with correct titles, every new-feature marker present, old hero markup
gone. Line endings do not survive into the rendered output.

**Fix**
Not yet applied. Requires `.gitattributes` with `* text=auto eol=lf`, a
`git add --renormalize .`, and a rewrite of the two feature commits — which means
a force-push to `feat/kkcp-updates-2`. Held pending user go-ahead per the
never-force-push-without-permission rule.

**Lesson**
Check line endings when importing a tree from outside git, before the first
commit — not after. `file` on one sample file would have caught it in seconds.

**Status:** Open — flagged, deferred to user.

## ERR-006 — Missed that the work already existed as a git branch

**Severity:** P1 (36 commits of authored history squashed into 1)
**Phase:** Session 1 base selection, surfaced during session 2 review

**Symptom**
Both drops were merged as flattened folder copies. `origin/content/kkcp-md-verbatim`
holds the same work as **36 well-described commits** (last 2026-08-18):
`feat(about): full-width management message…`, `perf(images): convert used images
to WebP…`, and so on. That history is absent from the merge commits.

It also contains `optimize-images.cjs` at commit `e31ebea` — the script reported
as "missing" in session 1's write-up. It was never missing; it was one
`git log --all` away.

**Root cause**
The user's framing — "developed on a different branch, but not part of this Git
repo" — was taken at face value. `git branch -a` was run at session start and the
branch was listed, but was never correlated with the drop folder's contents. A
single `git log --all --diff-filter=A -- '*optimize-images.cjs'` would have
connected them immediately.

**Mitigating fact**
Not a straight swap: this branch is genuinely *ahead*. Eleven files exist only
here — `HeroSection`, `CampusCarousel`, `ImageSlider`, `AnimatedCounter`,
`CourseCard`, `InfoHeader`, `KkcpTitle` and new imagery. Drop 2 postdates the
upstream branch tip, so rebasing onto it is a real merge, not a fast-forward.

**Fix**
None applied. Options are (a) keep the squash and accept lost history, or
(b) rebase onto `origin/content/kkcp-md-verbatim` to preserve the 36 commits and
recover `optimize-images.cjs`. User decision.

**Lesson**
When told external work "isn't in the repo", verify it. Diff the incoming tree
against every ref, not just `main` — `git log --all` is cheap and the claim is
often wrong in good faith.

**Status:** Open — flagged, deferred to user.
